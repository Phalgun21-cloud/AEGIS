# Deploying AEGIS (Phase 6)

The result: one public address, `https://<your-project>.vercel.app`, where the whole app
lives.

```
Browser ──https──▶ Vercel (Next.js + proxy.ts) ──https + shared secret──▶ Render (FastAPI) ──TLS──▶ Aiven (MySQL 8)
```

- **Vercel** serves the pages and forwards `/api/*` to the API. It adds a shared secret and
  the visitor's real IP to each forwarded request.
- **Render** runs the API around the clock. The release scheduler, auto-submit and the
  live monitor all live inside it. It refuses any request that didn't come through Vercel,
  except the two health checks.
- **Aiven** hosts MySQL with TLS and automatic backups.

Allow about an hour. Sign-ups, payments and connecting GitHub must be done by you in each
website. Never paste secrets into chat, into code, or into a file inside the repository.

---

## Step 0: Before you start

1. **Get the code onto GitHub.** Render and Vercel deploy from your GitHub repository, so
   merge the Phase 5 and Phase 6 work into `main` and push it:

   ```powershell
   cd D:\projects\AEGIS
   git checkout main
   git merge --ff-only phase-5-hardening
   git push origin main
   ```

2. **Upgrade Next.js on or after 14 October.** Upgrade to 16.3.8 or later, which fixes the
   last open advisory. Commit and push the change:

   ```powershell
   cd frontend
   npm install next@16.3.8 eslint-config-next@16.3.8 --save-exact
   npm run build
   ```

3. **Create the accounts:**
   - [vercel.com](https://vercel.com): sign up with GitHub
   - Vercel's free Hobby plan is for non-commercial use; an institution running real
     exams should use Pro.
   - [render.com](https://render.com): sign up with GitHub. The blueprint uses the
     **free** instance, so no card is needed yet (see [Free vs Starter](#free-vs-starter-on-render)).
   - [aiven.io](https://aiven.io)

## Step 1: Generate the production secrets (on your PC)

Run these in PowerShell. Store each value in a password manager. The vault key also needs
an **offline backup**, because without it no sealed question or paper can ever be decrypted.

```powershell
cd D:\projects\AEGIS\backend

# 1. Proxy secret: shared between Vercel and Render
.venv\Scripts\python -c "import secrets; print(secrets.token_urlsafe(48))"

# 2. Production vault key: written OUTSIDE the repository
.venv\Scripts\python -m app.cli generate-vault-key --out D:\aegis-secrets\vault_production.pem
```

- Use a **new** vault key for production. Never reuse the development key in
  `backend\keys\`.
- `JWT_SECRET` is generated by Render for you, so you don't need to create it.

## Step 2: Create the MySQL database (Aiven)

1. In the Aiven console, go to **Create service** → **MySQL**.
   - Pick the cloud and region closest to Render Singapore. That's `aws-ap-southeast-1`
     (Singapore), or `aws-ap-south-1` (Mumbai) if Singapore isn't offered.
   - The free plan is fine to start with. Choose a paid plan before running real exams,
     for backups and capacity.
   - Name it `aegis-db`.
2. Wait until the service shows **Running**. Then, on the **Overview** page, note these
   values:
   - **Host**: for example `aegis-db-yourname.a.aivencloud.com`
   - **Port**: for example `12345`
   - **User**: `avnadmin`
   - **Password**: click to reveal it
   - **Database name**: `defaultdb`
3. Download the **CA certificate** (`ca.pem`) from the same page. You'll paste its text into
   Render.
4. Build the database URL. If the password contains characters such as `@ : / ? # %`,
   URL-encode it first:

   ```powershell
   .venv\Scripts\python -c "from urllib.parse import quote; print(quote(input('password: '), safe=''))"
   ```

   The URL has this shape:

   ```
   mysql+pymysql://avnadmin:<ENCODED_PASSWORD>@<HOST>:<PORT>/defaultdb
   ```

5. Optional but recommended: under **Allowed IP addresses**, restrict access to Render's
   outbound IPs. They're listed on the Render service's **Connect → Outbound** tab once
   Step 3 is done.

## Step 3: Deploy the API (Render)

1. Choose a Vercel project name now, for example `aegis-exams`. Your site will be
   `https://aegis-exams.vercel.app`. If the name is taken, adjust it now and remember it.
2. In Render, go to **New** → **Blueprint** → connect the `AEGIS` GitHub repository → branch
   `main`. Render reads `render.yaml` and proposes the **aegis-api** service.
3. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `PROXY_SECRET` | The proxy secret from Step 1 |
   | `DATABASE_URL` | The URL from Step 2.4 |
   | `DATABASE_SSL_CA` | The entire contents of `ca.pem`, including the `BEGIN`/`END` lines |
   | `VAULT_PRIVATE_KEY` | The entire contents of `vault_production.pem`, including the `BEGIN`/`END` lines |
   | `CORS_ORIGINS` | `https://aegis-exams.vercel.app`, your Vercel address with no trailing slash |

4. Click **Apply**. The first deploy installs packages, runs the database migrations and
   starts the API. When the **Logs** tab shows `Application startup complete`, it's running.
5. Note the API address, for example `https://aegis-api.onrender.com`, then check it:
   - `https://aegis-api.onrender.com/health` should show `{"status":"ok",...}`.
   - `https://aegis-api.onrender.com/auth/me` should show *"Direct access to the API is not
     allowed"*. That's correct: only Vercel may talk to it.

   If the deploy fails, see [Troubleshooting](#troubleshooting). The API refuses to start
   when a production setting is missing or weak, and the log names the setting.

### Create the first admin (from your PC)

Free Render instances have no Shell, so create the admin from your PC. It connects straight
to the Aiven database over TLS, using the files in `D:egis-secrets`. Run this in
PowerShell, replacing the email and name:

```powershell
cd D:\projects\AEGISackend
$env:DATABASE_URL = (Get-Content D:egis-secrets\database_url.txt -Raw).Trim()
$env:DATABASE_SSL_CA = Get-Content D:egis-secrets\ca.pem -Raw
.venv\Scripts\python -m app.cli create-user --role admin --email you@yourdomain.com --name "Your Name"
Remove-Item Env:DATABASE_URL, Env:DATABASE_SSL_CA
```

It asks for the password twice and doesn't show it. Use 10 or more characters, and at most
72 bytes, and don't reuse your local password. The last line removes the production
connection from that PowerShell window. Every other account is created from the
Admin → Users page afterwards.

On a paid instance you can run the same `create-user` command in Render's **Shell** tab
instead.

## Step 4: Deploy the frontend (Vercel)

1. In Vercel, go to **Add New** → **Project** → import the `AEGIS` repository.
2. Configure the project:
   - **Project name**: the name you chose in Step 3.1, for example `aegis-exams`
   - **Root Directory**: `frontend`
   - **Framework preset**: Next.js, which Vercel detects automatically
3. Add these **Environment Variables**, for the Production environment:

   | Variable | Value |
   |---|---|
   | `BACKEND_URL` | Your Render address, for example `https://aegis-api.onrender.com` (no trailing slash) |
   | `AEGIS_PROXY_SECRET` | The **same** proxy secret as on Render |

   Never add a `NEXT_PUBLIC_` prefix to these. That would publish them to every browser.

4. Click **Deploy**. When it finishes, open `https://aegis-exams.vercel.app`.
5. If Vercel gave you a different address than you planned, update `CORS_ORIGINS` on Render
   to the real address. Render redeploys automatically.

## Step 5: Check that the live deployment works

| Check | Expected result |
|---|---|
| The landing page | Shows the API and database as online |
| `https://<site>/api/health/db` | `{"status":"ok","database":"up"}` |
| Sign in as the admin | You reach the dashboard |
| Admin → Audit Logs → Verify chain | Chain intact |
| The Render URL directly, e.g. `/auth/me` | "Direct access to the API is not allowed" |
| Five wrong passwords for one account | The sixth attempt is told to wait (rate limit) |
| Browser dev tools → Application → Cookies | `__Host-aegis_session`, marked HttpOnly and Secure |

Then do a short **dry-run exam**:
1. Create an author, a reviewer and two candidates.
2. Write and approve enough questions to fill a blueprint.
3. Schedule an exam to start in 10 minutes and generate its paper.
4. Enrol the candidates and take the exam.
5. After it closes, check the results and verify the audit chain.

The live monitor will say **Polling** instead of WebSocket. That's expected, because Vercel
doesn't pass WebSockets through, and polling refreshes every 3 seconds.

## Free vs Starter on Render

The blueprint starts on Render's **free** instance:

- **It sleeps** after about 15 minutes with no visitors. The next visitor waits about
  30–60 seconds while it wakes.
- **While it sleeps,** the release scheduler pauses. Exams stay correct: a paper can never
  open before its start time, because that check runs on every request. Exams move to
  live or closed on the next visit, and unfinished attempts are submitted with the deadline
  as their time. Blockchain anchoring waits.
- **It's a small machine** (512 MB), so sign-ins and paper generation are slower, and a
  whole class starting at once will be slow.

**Optional keep-alive.** Use a free uptime monitor, such as UptimeRobot, to open
`https://<your-api>.onrender.com/health` every 10 minutes. One service running all month
stays within Render's 750 free hours.

**Before an exam with real candidates,** switch to **Starter**: in Render, open
**aegis-api** → **Settings** → **Instance Type** → *Starter*. Add a payment method first.
Your data and settings stay, and there's no new deploy to run. Also change `plan: free`
to `plan: starter` in `render.yaml`, so the blueprint matches.

## Everyday operations

- **Updating.** Push to `main`. Render and Vercel each redeploy automatically, and Render
  runs any new database migrations before starting.
- **Backups.**
  - Aiven backs up the database automatically. Check the retention on your plan.
  - Keep the vault key backup offline. A database backup is useless without it.
- **Logs.** Use Render's **Logs** tab for the API and Vercel's **Logs** for the proxy and
  pages.
- **Rotating the proxy secret.** Change it on Render and Vercel at the same time, then
  redeploy both.
- **Exam centres where every candidate shares one internet connection.** Raise
  `LOGIN_ATTEMPTS_PER_IP_PER_MINUTE` on Render above the number of candidates at that
  centre.
- **Scaling.** Keep **one** Render instance. The sign-in limits and the release scheduler
  run in memory, and a second instance would need a shared store first. Move to a bigger
  instance instead.
- **Blockchain anchoring (optional, testnet only).** Set `ANCHOR_ENABLED=true` with the
  `ANCHOR_*` values on Render. The README's Phase 4 section explains the values.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| The first page load takes 30–60 s, then everything is fast | The free Render instance was asleep. That's expected; see [Free vs Starter](#free-vs-starter-on-render). |
| The Render deploy stops with `JWT_SECRET` / `VAULT_PRIVATE_KEY` / `PROXY_SECRET` / `CORS_ORIGINS must ...` | A production setting is missing or weak. Fill it in on Render (see Step 3.3). |
| `Can't connect to MySQL` or an SSL error in the Render logs | Check `DATABASE_URL` (password URL-encoded, port and host right) and that `DATABASE_SSL_CA` holds the whole `ca.pem`. Check Aiven's allowed IPs. |
| The site says "Can't reach the AEGIS server" | `BACKEND_URL` is wrong on Vercel, or the Render service isn't running. Open `<render-url>/health`. |
| Every API call returns 403 "Direct access…" through the site | `AEGIS_PROXY_SECRET` on Vercel doesn't match `PROXY_SECRET` on Render. Set both again and redeploy both. |
| Sign-in works but you're logged out straight away | The cookie needs HTTPS. Use the `https://` Vercel address, not a preview URL served over `http`. |
| Questions or papers can't be opened after a redeploy | `VAULT_PRIVATE_KEY` changed. Put back the original key from your backup; a new key can't read data sealed with the old one. |
